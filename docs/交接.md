1. 读 [`architecture.md`](architecture.md) 的依赖、运行生命周期和发布模型。
2. 读本文的“架构不变量”和“已知坑”，避免把拆分后的 partial 当成完整文件。
3. 按“构建与验证”跑一遍构建、xUnit、架构门禁和原生烟测。
4. 修改检测逻辑前读 [`data-model.md`](data-model.md) 的 CSV 映射、无效值、规则管线与报告列。
5. 任何发布相关改动先跑发布姿态、包健康和安装器烟测，不要只看本地 `dotnet build`。

## 构建与验证

### 环境

- Windows 10/11 x64。
- .NET SDK `11.0.100`（`global.json`，`rollForward=latestFeature`）。
- PowerShell 7（`pwsh`）。部分脚本使用 .NET Core 的 `ProcessStartInfo.ArgumentList`，Windows PowerShell 5.1 会失败。
- Windows App SDK `2.6.5` 由 NuGet 还原；无需单独安装 Windows App Runtime。
- 安装器需要 Inno Setup 7.1.1（脚本兼容 Inno Setup 6）。

### 构建、测试、门禁

```powershell
dotnet restore .\desktop\EDetection.Desktop.slnx
dotnet build .\desktop\EDetection.Desktop.slnx -c Debug --no-restore
dotnet format .\desktop\EDetection.Desktop.slnx --verify-no-changes --no-restore
dotnet test .\desktop\EDetection.Tests\EDetection.Tests.csproj -c Debug --no-build
pwsh -NoProfile -ExecutionPolicy Bypass -File .\desktop\scripts\Test-DesktopArchitecture.ps1 -NoBuild
pwsh -NoProfile -ExecutionPolicy Bypass -File .\desktop\scripts\Test-DesktopNativeBackendSmoke.ps1 -NoBuild
```

除无界面基础冒烟外，原生烟测还会运行 `--regression all` 的 20 个命名回归（含 `harness`）。它会在启动时断言未加载 `Microsoft.WindowsAppRuntime`、`Microsoft.UI.Xaml` 或 `WinUIEx`。

### 发布与安装

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\desktop\scripts\Publish-Desktop.ps1 -RuntimeIdentifier win-x64
pwsh -NoProfile -ExecutionPolicy Bypass -File .\desktop\scripts\Test-DesktopPackageHealth.ps1 -PackagePath .\artifacts\desktop\win-x64\publish
pwsh -NoProfile -ExecutionPolicy Bypass -File .\desktop\scripts\Build-DesktopInstaller.ps1 -RuntimeIdentifier win-x64
pwsh -NoProfile -ExecutionPolicy Bypass -File .\desktop\scripts\Test-DesktopInstallerSmoke.ps1 -InstallerPath .\artifacts\desktop\win-x64\installer\EDetection-Setup-win-x64.exe
pwsh -NoProfile -ExecutionPolicy Bypass -File .\desktop\scripts\Test-DesktopInstallSmoke.ps1 -PackagePath .\artifacts\desktop\win-x64\publish
```

安装方式：

- **推荐**：运行 `EDetection-Setup-win-x64.exe`。默认安装到 `%LOCALAPPDATA%\Programs\EDetection`，按用户安装，不需要管理员权限；升级用新版安装器覆盖。
- **便携安装**：解压 `EDetection-win-x64.zip`，运行 `Install-Desktop.ps1`；可用 `-NoDesktopShortcut` / `-NoStartMenuShortcut` 跳过快捷方式。
- **卸载**：Windows“已安装的应用”或安装目录的 `unins000.exe`；便携安装运行 `Uninstall-Desktop.ps1`。默认保留用户设置，只有 `-RemoveSettings` 才删除。

`v2.0.2` 安装器与便携包有意保持未签名；Windows 可能显示未知发布者或 SmartScreen 提示。SHA-256 仅验证文件完整性，不能验证发布者身份。

## 架构不变量

- **WinUI-free**：`EDetection.Domain` 与 `EDetection.Desktop.Core` 不得引用 `Microsoft.WindowsAppSDK`、`Microsoft.WinUI` 或 `UseWinUI`。xUnit `ArchitectureTests` 和架构门禁同时检查。
- **核心可独立运行**：`EDetection.NativeCore` 不依赖 WinUI/Windows App SDK；`EDetection.Desktop.Tests` 启动时断言未加载 UI 运行时。
- **规则入口单一**：行级规则只通过 `DetectionRowRulePipeline` 执行，顺序固定为电压 → 电流 → 有功功率 → 功率因数 → 温度；`Analysis.cs` 不直接调用单个规则。冻结/恒定由 `FreezeRowDetector` 在整列序列上执行后追加到行结果。
- **单一后端**：`native` 是唯一检测实现。任何重新引入 Python 运行时、wheelhouse、进程桥接或 `build/E-Detection` 的改动都视为架构回退。
- **partial 行数上限**：`MainViewModel.cs` ≤ 600；`NativeDetectionBackendService.cs` ≤ 120；每个 `SettingsView*.cs` ≤ 450；每个后端/`MainViewModel` partial ≤ 800。
- **中央包管理**：包版本只在 `Directory.Packages.props` 声明；项目文件中的 `PackageReference` 不允许带 `Version=`。
- **报告原子性**：先写同目录临时文件，校验 ZIP 条目和 XML，再 `File.Move` 到最终名；失败必须清理临时文件。
- **密钥不进设置**：LLM API Key、ntfy Token、代理密码只存 Windows Credential Locker；`settings.json` 不含密钥。
- **安装路径安全**：发布/安装/卸载脚本只允许 canonical 路径包含关系；安装器拒绝磁盘根、用户根、桌面、`Program Files` 等位置。

## 已知坑

### 拆分后的 partial 与静态脚本

`SettingsView`、`NativeDetectionBackendService`、`MainViewModel` 都是 partial family。静态烟测按 glob 扫描：

- 架构门禁扫描 `SettingsView*.cs`、`NativeDetectionBackendService*.cs`、`MainViewModel*.cs`。
- 设置/可选网络烟测扫描 `MainViewModel*.cs`（不是 `SettingsView*.cs`）。Stage 5 拆分后 `_networkProxy.BuildHandler(this, useProxy: true)` 从 `MainViewModel.cs` 移到 `MainViewModel.SettingsCommands.cs`；烟测原先只 grep `MainViewModel.cs`，CI 因此误报。现在按文件名排序读取全部 `MainViewModel*.cs`。
- 发布姿态烟测扫描 `MainViewModel*.cs`，避免升级器文案藏在 partial 中而漏检。

新增一个 partial family 时，必须同步检查这些脚本的 glob、行数上限和期望文本，否则门禁可能“绿但漏检”。

### 规则顺序与字符串契约

- `DetectionRowRulePipeline.Default` 的顺序、`DetectionRowContext.VoltageColumnCount` 的全零行语义、`FreezeRowDetector` 的平坦/待机判定都属于检测契约；修改前先补 `DetectionRulePipelineTests`。
- `detail_output=false` 时，电流过大和温度异常按超限相重复通用标签；不要为了“去重”改变行级重数，后续结构化明细和文件摘要依赖它。
- `NativeDetectionBackendService.Rules.cs` 已不再是规则所有者，只保留离线无效计数与传感器状态辅助；新增行规则应放入 `Detection/`，配置映射放入 `NativeDetectionBackendService.RuleOptions.cs`。

### xUnit v3 与 Microsoft.Testing.Platform

`global.json` 固定：

```json
{
  "test": {
    "runner": "Microsoft.Testing.Platform"
  }
}
```

`EDetection.Tests` 是 xUnit v3 可执行测试项目，不是传统 VSTest 项目。不要删除该 runner 配置，也不要把 `dotnet test` 换成只认 VSTest 的自定义命令。先构建再 `dotnet test ... --no-build`。

### Inno Setup 路径

`Build-DesktopInstaller.ps1` 按以下顺序查找 `ISCC.exe`：

1. `-IsccPath`。
2. `$env:ISCC_PATH`。
3. PATH 中的 `iscc.exe`。
4. `%LOCALAPPDATA%\Programs\Inno Setup 7\ISCC.exe`。
5. `C:\Program Files\Inno Setup 7\ISCC.exe` / `C:\Program Files (x86)\Inno Setup 7\ISCC.exe`。
6. 同上的 Inno Setup 6 路径。

CI 固定下载 Inno Setup 7.1.1 并校验 SHA-256。本地找不到时传 `-IsccPath`，不要修改安装器去绕过。

### 自包含 WinAppSDK

`WindowsAppSDKSelfContained=true` 与 `WindowsPackageType=None` 必须同时保留。只设 `SelfContained=true` 只打包 .NET 运行时，干净机器会缺少 Windows App Runtime 而无法启动。包健康检查会验证 `Microsoft.WindowsAppRuntime.dll`、`Microsoft.UI.Xaml.dll`、`CoreMessagingXP.dll`、`DWriteCore.dll`、`MRM.dll`。

### PowerShell 版本

原生烟测脚本通过 `ProcessStartInfo.ArgumentList` 传参；Windows PowerShell 5.1 的 .NET Framework 实现没有该属性，会报“不能对 Null 值表达式调用方法”。统一用 `pwsh` 运行脚本。

### 陈旧产物

`Publish-Desktop.ps1` 会清理 `artifacts/desktop/<rid>/publish`，但旧的 ZIP、安装器和 `install-files.txt` 可能残留。安装器构建会先跑包健康并清空 installer 输出目录；如果出现文件清单不一致，先重新发布再构建安装器，不要手工改 `install-files.txt` 掩盖问题。

### 未签名发布

`v2.0.2` 强制未签名（工作流中 `$forceUnsigned = $tag -eq "v2.0.2"`）。没有证书时不要声称产物已验证发布者；SHA-256 只证明文件完整性。
